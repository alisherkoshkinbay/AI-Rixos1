# QONAQ: 5 паттернді оқытушыға түсіндіру

## 1. Factory Method — өнімді жасау

**Неге керек?** Бір үлкен `if/else` ішінде тағам, сусын, десертті жасаудың орнына әр санаттың фабрикасын ажыратамыз.

- `MenuFactory` — абстрактілі фабрика, `create(...)` әдісін жариялайды.
- `FoodFactory`, `DrinkFactory`, `DessertFactory` — `create(...)` әдісін іске асырады, өнімнің категориясын өзі тағайындайды.
- `RestaurantFacade` барлық үш фабриканың `catalog()` нәтижесін біріктіреді.

**Демо:** Мәзірден `Тағамдар`, `Сусындар`, `Десерттер` сүзгілерін ашып көрсетіңіз.

## 2. Builder — толық тапсырыс жинау

**Неге керек?** Тапсырыста клиент, телефон, жеткізу тәсілі, адрес, промокод, бірнеше позиция болады. Бір ұзын конструкторға барлық параметрді беру ыңғайсыз.

- `OrderBuilder.customer(...).phone(...).fulfillment(...).addItem(...).discount(...).build()`.
- `build()` клиент атын, телефонды, жеткізу адресін және тауарларды тексереді.
- Дұрыс болса, `Order` объектісін қайтарады.

**Демо:** Себетке тағам салып, checkout-ты ашыңыз. Бос клиент атымен тапсырыс жіберіңіз: валидация хабарламасы көрінеді.

## 3. State — тапсырыс күйін басқару

**Неге керек?** Әр статус кезінде барлық әрекетке рұқсат берілмейді.

`NEW → PREPARING → READY → COMPLETED`

`NEW` және `PREPARING` күйлерінен `CANCELLED` күйіне өтуге болады; `READY` немесе `COMPLETED` күйінен бас тартуға болмайды.

- `OrderState` интерфейсі — `advance(Order)` және `cancel(Order)`.
- `States` ішіндегі жеке күй класстары өз ережесін іске асырады.
- `Order.next()` және `Order.cancel()` барлық шешімді ағымдағы күйге тапсырады.

**Демо:** `Тапсырыстар` бөлімінде `Дайындауды бастау` → `Дайын деп белгілеу` → `Тапсырысты аяқтау` батырмаларын басыңыз. Аяқталған тапсырысты қайта өзгерту мүмкін емес.

## 4. Observer — оқиғаға автоматты жауап

**Неге керек?** Бір тапсырыс өзгергенде экрандарды өзгерту логикасын әр жерге таратпаймыз.

- `OrderEvents` — тыңдаушылар тізімі, `subscribe(...)` / `publish(...)`.
- `OrderObserver` — хабарлама қабылдайтын интерфейс.
- `RestaurantFrame` қызметке жазылып, тапсырыс өзгергенде экранды жаңартады және төменде хабарлама көрсетеді.

**Демо:** Тапсырыстың статусын өзгертіңіз — тізім, статистика мен төменгі хабарлама жаңарады.

## 5. Facade — қарапайым бірыңғай API

**Неге керек?** UI әр фабриканы, тапсырыс құрастыруды, репозиторийді, статус ауыстыруды және хабарламаларды жеке-жеке басқармауы тиіс.

- `RestaurantFacade.addToCart()` — себетке қосу;
- `RestaurantFacade.checkout()` — Builder арқылы тапсырыс құру, файлға сақтау, Observer хабарламасын жариялау;
- `RestaurantFacade.advance()` / `.cancel()` — State арқылы ауысу және сақтау;
- `RestaurantFacade.revenue()` / `.popularProducts()` — аналитика.

**Демо:** Мәзірден өнім қосып, заказ жасаңыз. Әр бөлік өз қызметін атқарса да, UI `RestaurantFacade` арқылы байланысады.

## Функциялардың тізбегі

```text
[User clicks Checkout]
       |
       v
[MenuPage / CheckoutDialog] -- UI
       |
       v
[RestaurantFacade.checkout()] -- FACADE
       |
       +--> [OrderBuilder.build()] -- BUILDER
       |
       +--> [OrderRepository.save()] -- PERSISTENCE
       |
       +--> [OrderEvents.publish()] -- OBSERVER
                                      |
                                      v
                              [RestaurantFrame refresh]

[User clicks Next Status]
       |
       v
[RestaurantFacade.advance()] -- FACADE
       |
       v
[Order.next() -> OrderState.advance()] -- STATE
```

Каталогты құру кезеңінде `MenuFactory` және оның үш нақты фабрикасы қолданылады — **FACTORY METHOD**.

**Ескерту:** Бұл бір компьютерге арналған offline desktop симуляциясы. Нақты төлем шлюзі мен multi-user сервер құрылмаған.
